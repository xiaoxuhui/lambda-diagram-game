# 符号微积分修正需求与设计

用户指出原定积分示例已经使用积分后的表达式。确认为产品缺陷：已有积分只计算已知原函数差，未生成原函数；已有导数为双数自动微分，并非符号求导。保留事实记录，不把旧演示称为符号微积分。

修正限定为多项式：输入原多项式系数数据，Lambda程序实际生成导函数/原函数系数，再求值或作上下限差。系数使用非负有理数，指数为自然数。原函数取积分常数0；不支持任意函数、负系数或自动推断原函数。

用Church列表（按次数降序）编码系数，用Church有序对编码有理数。符号求导遍历原列表，按次数乘系数并去除常数；符号积分按次数+1除系数，并追加0常数。均以真实β归约执行，JavaScript只生成输入编码和展示已归约结果，不预先求导或积分。

新增独立的符号求导/积分结果示例，显示原式及真实生成的多项式；既有数值例改为调用同一符号算法后求值。格式器识别正规形中的有理数/多项式，支持约分显示；存档仍保存完整AST与每步轨迹，不修改格式。

验收：变更原系数后导函数/原函数改变；导数例(x²+3x)生成2x+3，积分2x生成x²；x、x²等积分保留1/2、1/3系数；常数、零、分数系数有正确结果；定积分0至3的2x确经生成原函数后得9。单元、桌面/手机与存档重载验证。
