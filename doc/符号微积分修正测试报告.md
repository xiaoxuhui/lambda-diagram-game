# 符号微积分修正测试报告

2026-10-24。此前积分演示直接计算给定原函数差，导数演示为双数自动微分；它们不能证明已从原多项式生成原函数/导函数。此次替换为真正的多项式符号转换，不保留旧预置原函数的实现。

## 原式与算法

输入原多项式系数，按降序编码为Church列表，每个系数为有理数对。`diff`实际遍历并乘次数、移除常数，`integ`实际遍历并除以次数+1、追加0常数。`evalpoly`随后求值，`rsub`求上下限差。所有转换与计算通过现有β归约引擎执行，JavaScript没有计算导系数/积分系数，只负责输入编码和已归约结果格式化。

- x²+3x → 2x+3；换成3x² → 6x。
- 2x → x²，x → 1/2x²，3x² → x³，常数5 → 5x。
- x²+3x积分生成1/3x³+3/2x²，分数保持精确。
- 从原2x先生成原函数，再求0到3的定积分9；从原x求0到1的积分得到1/2。

新生成程序无需预置导函数/原函数，四个示例Lambda原串长度分别663/903/394/351字符，均低于既有1500输入预算。输入变更测试不依赖示例期望文本。

## 范围

支持非负有理系数、自然数指数多项式；原函数取C=0。定积分端点自然数且a≤b，保证当前自然数编码可表达结果。不是任意Lambda函数或sin/exp/log的通用符号积分器；不支持负系数或负结果。没有更改存档格式、核心β规则、线条数量或步数限制，也未发布APK/大厅新版本。
