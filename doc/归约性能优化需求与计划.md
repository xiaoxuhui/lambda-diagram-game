# 长表达式归约性能：需求、设计与实施计划

- **Status**: VERIFIED
- **Approved**: 2026-10-09 用户要求优化长表达式、少量归约仍卡顿的算法
- **Type**: refactor

## 需求与验收

U01 左最外正常序、变量防捕获、内部归约、实际尝试后停止及全部既有运算结果保持不变。

U02 保留所有变量、线条、完整表达式及每一步历史，不设置数量限制，不压缩、截断、折叠计算结构。

U03 用同一脚本与同一 Node 比较改动前后：一个归约项旁边的大型正规子树、深层替换、多次查找/格式化；增加浏览器中的完整内容与无变化界面刷新检查。

## 设计边界

使用不可变 AST 和 WeakMap 保存已计算的节点统计及是否含可归约项；只更新变化分支的数据。避免重复复制完整路径、重复自由变量扫描和无变化节点重建。长链遍历改用显式栈。界面保留完整绘制，对未变化的表达式避免重新创建 SVG 和历史 DOM。所有缓存只是附加信息，序列化与图示仍输出完整结构。
